# Self-audit (model)

- [critical] Unbacked virtual escrow pays bounties directly from treasury balance: _complete() only credits escrowed[taskId]=BOUNTY and totalEscrowed without moving tokens. claimTask()/claimCompensation()/cleanupStaleEscrow() then call _payBounty() which does balanceOf[treasury]-=esc; balanceOf[to]+=esc. poolReserve and contract balance are never debited. fundBountyPool() locks treasury tokens in contract/poolReserve but claims do not consume them, breaking poolReserve==backing invariant and allowing infinite drain of treasury up to MAX_TREASURY_SPEND_PER_EPOCH per epoch. | fix: Lock funds at completion: transferFrom treasury or from poolReserve/contract to escrow, debit poolReserve, and pay claims from contract balance. Require poolReserve>=totalEscrowed invariant and decrement both on payout/cancel/slash.
- [critical] Treasury approval never enforced, single reviewer can mint payouts: approveTask() sets treasuryApproved/task expiry but _complete() never requires treasuryApproved[taskId] nor checks treasuryApprovalExpiry. Any single isReviewer address can call completeTask()/completeTaskWithReason() on any eligible task, creating BOUNTY escrow. This is vote/ticket manipulation and access-control bypass enabling reviewer-submitter collusion to drain treasury. | fix: Require treasuryApproved[taskId]==true and block.timestamp<=treasuryApprovalExpiry[taskId] in _complete(), consume approval on use, or require multi-reviewer/quorum.
- [high] treasuryHalted does not stop bounty claims: _complete(), _withdrawFees(), _withdrawPool() revert if treasuryHalted, but claimTask(), claimCompensation(), cleanupStaleEscrow() and _payBounty() have no halt check. Escrowed tasks remain payable from treasury during emergency, defeating halt as drain circuit-breaker. | fix: Check treasuryHalted in _payBounty() and all claim/cleanup paths, or add separate pause that blocks claims.
- [high] Single-reviewer completion with guardian-only slashing enables farming: No quorum, stake requirement, or cooldown by default (reviewerCooldown=0). Reviewer can complete up to maxPerReviewer/BOUNTY tasks and colluding submitters holding MIN_HOLDING with MAX_OPEN=3 each can cycle submit->complete->claim. Treasury spend cap is 500000e18 per 30 days on 1000000e18 supply, so full drain in ~2 epochs. resolveDispute() slashing up to 2*BOUNTY is sole deterrent and requires guardian/owner action. | fix: Require quorum/multiple reviewers, mandatory reviewer stake, enforce treasury approval, lower per-epoch spend, add per-reviewer/submitter rate limits and linkability checks.
- [medium] Global per-block submit limit allows griefing DoS: submitTask() enforces global MAX_SUBMITS_PER_BLOCK=20 via lastSubmitBlock/submitsThisBlock. Any holder can fill 20 slots in a block to censor others. Combined with MAX_OPEN=3 and 30-day TASK_EXPIRY where openCount only decrements on claim/cancel/expire, a submitter is locked if reviewers withhold completion. | fix: Use per-account rate limit instead of global, add pagination/cap exceptions, allow submitter to force-expire or replace, decrement openCount on completion or add timeout.
- [medium] Unbounded bulkCancel loop risks gas DoS: bulkCancel(uint256[] calldata ids) loops over arbitrary-length ids with storage reads/writes and no length cap, callable by owner/reviewers. Large arrays can exceed block gas and always revert, blocking legitimate cleanup. | fix: Cap ids.length (e.g. <=50), paginate, or make single-item cancellation the only path.
- [low] Zero-address checks missing/inconsistent: proposeGuardian() has no ZeroAddress check unlike setGuardian()/setReviewer()/proposeReviewer(), allowing guardian=address(0) via propose+confirm. approve() allows spender==address(0). treasury/owner/guardian are immutable with no recovery; if treasury lost, fundBountyPool/claims halt and poolReserve locks. | fix: Add require(g!=address(0)) to proposeGuardian(), require(spender!=address(0)) in approve(), add timelocked treasury/owner rotation with zero checks.
- [info] Reentrancy, integer math and holding checks: No ETH or external token calls; all payouts are internal balance ledger updates with checks-effects-interactions and nonReentrant on claim/unstake/withdraw, so classic reentrancy is not exploitable, though nonReentrant reuses Paused() error confusingly. Solidity 0.8.26 checked math makes overflow safe; fee amount*50/10000 cannot overflow 1M supply. MIN_DESC_LEN=100, MAX_DISPUTE_BOND, MAX_PER_REVIEWER_CAP constants defined but MIN_DESC_LEN never enforced; maxDescLen timelock is enforced. | fix: Keep nonReentrant, use dedicated Reentrancy error, enforce MIN_DESC_LEN if intended, add invariant tests for bal>=totalStaked+poolReserve+feeReserve.
