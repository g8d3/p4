# Self-audit (model)

- [high] Predictable blockhash randomness with selective draw timing: drawWinner uses uint256(blockhash(block.number-1)) % len. Value is publicly known before draw transaction executes and is manipulable by block producers. Since drawWinner is permissionless, an attacker can preview outcome off-chain and only call draw when hash favors them, or validator can withhold/choose to influence winner. | fix: Use Chainlink VRF, RANDAO with future block commitment, or commit-reveal: store request block, draw in later transaction after hash is fixed and unknown at entry close.
- [high] Sybil / point-in-time entry allows ticket manipulation: enter() only checks _balances[msg.sender] >= MIN_ENTRY_BALANCE at entry time. No stake, lock, snapshot, or balance requirement at draw. Attacker can split 1M supply into ~1000 addresses to get ~1000 tickets, then consolidate/sell immediately and still win. Flash-funded wallets can enter for free. | fix: Require lock/stake of MIN_ENTRY_BALANCE, snapshot balances at round end, or require holding at draw time; consider entry fee or one-ticket-per-unit-staked.
- [medium] Residual treasury permanently locked, no sweep: Prize is 90% of roundFees. Remaining 10%, fees of rounds with zero entries, rounding dust, and direct transfers to contract increase _balances[address(this)] but have no withdraw, sweep, or void-round handling. Funds locked forever. | fix: Add onlyOwner/governance sweep of remainder after claim + timeout, void-round handling, or pay 100% to winner; add rescue for dust.
- [low] DoS / unbounded enumeration and empty rounds: getEntries() copies full _entries[roundId] array; storage grows unbounded per round. drawWinner reverts on len==0, leaving that round's fees irrecoverable. Max per-round entries ~1000 due to supply/1000 cap, so gas impact limited but view can become heavy. | fix: Paginate getEntries, cap entries, allow marking empty round void and sweeping its fees.
- [info] Reentrancy: no external call vector: claimPrize has nonReentrant and checks-effects-interactions, but only updates internal _balances and emits events. No call/send/ERC777 hook, so reentrancy not exploitable. Guard is defense-in-depth. | fix: No fix needed; keep guard if external calls added later.
- [info] Access control minimal, draw permissionless by design: onlyOwner only gates transferOwnership with zero-check. enter/drawWinner/claimPrize permissionless as intended. No owner mint/pause/drain. Permissionless draw enables grinding noted above. | fix: If keeping insecure randomness, restrict drawWinner to owner/keeper; with VRF keep permissionless keeper with request/fulfill split.
- [info] Integer math safe with fee/prize truncation: Solidity 0.8.26 checked math prevents overflow; allowed - amount handled, infinite allowance respected. fee=amount/100 truncates, amounts <100 pay zero fee; prize=(fees*90)/100 truncates dust to contract. | fix: Document zero-fee for small transfers and dust retention; consider explicit minimum or rounding direction.
- [info] Zero-address validation present: transfer, transferFrom, _transferWithFee check from/to != zero, approve checks spender/sender, transferOwnership checks newOwner, drawWinner/claimPrize check winner != zero. | fix: No fix needed.
