Which columns matter for indexers

ColumnWhy it decides
type (5-way enum)Biggest fork: per-app subgraph vs framework vs unified API vs RPC-stream vs SQL warehouse. Filter this first.
chains_count + noteKills mismatches instantly (Solana-only Helius vs 200-chain SQD). Number sorts, note keeps it honest.
query_interfaceIntegration cost: frontend → GraphQL/REST, analysts → SQL, backends → streams/webhooks.
latency (streaming→warehouse)Trading bots need streaming; dashboards tolerate warehouse. Sort fastest-first.
pricing_model + free_tierBill shape + can-I-prototype-today. Split in two columns, never one mushy "price" cell.
decentralization + self_hostTrust/lock-in axis and the exit option. $0 self-host (Ponder/Checkpoint) vs hosted SaaS.
verified + source_urlPricing rots quarterly — every row carries its evidence date + link. Raw data: /api/indexers.

How to pick a skill — what to look at

#Test (do it at 390px)What separates them
1Can you compare 3 indexers with one thumb, no horizontal scroll?m2 bottom-nav + m4 compare tray vs m1/m5 pure grids. Table-forks (m4) beat squished <table>s.
2Do targets hit 44px? Does content clear the notch/home bar?Only m2 was taught safe-area + 100dvh + 44px. Check others with a ruler, not trust.
3Does type grow without breakpoints breaking? (zoom to 400%)m1 container queries + m4 intrinsic auto-fit survive; fixed-breakpoint layouts (m3/m5) snap.
4Which columns survive on a phone?m3 Priority+ is explicit (name+type+latency stay, rest overflows). Others show all-or-nothing — ask which you'd drop.
5Distrust the vanity numbers40.3K stars on wshobson = whole repo, not this skill. Skill-specific signals: responsive-craft ★61, supercent 11.2K installs. Installs-per-skill > repo stars, always.
6Speed on a slow phonem5 (rem-only, smallest CSS) should win first paint; m2's fixed bars cost compositing. Time it, don't eyeball.
Short answer: default to m1 (wshobson) for general responsive work — most installs, modern primitives. Take m2 when the audience is phones-first (touch/safe-area/bottom-nav baked in). Take m4 when the page is a data table — it's the only skill with table forks. Use m3 when columns outnumber the screen (Priority+ discipline). Use m5 as the perf floor every other version must beat.
