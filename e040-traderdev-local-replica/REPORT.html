2. What is Monte Carlo? (and what we actually did)

Monte Carlo here is not generating fake signals. We took the real 112-132 realized trades of the EMA7 1-day version and asked: "if these exact trades had happened in a different ORDER (10,000 random shuffles), what would happen?" This tests whether the result depends on a lucky sequence. It does not: not one of the 10,000 shuffled paths ends negative.

4. The synthetic-data negative control (Phase 8)

The missing null: 60 pure-noise price series (random walk with BTC's real daily volatility, 2.47%/day) run through the same EMA7 daily machinery. If the machine prints profits on garbage, most of the edge is the machine, not the signal.

Result: on pure noise the machine still shows PF 1.42 median (90% of noise series profitable) — it is a drift-harvester. The real market structure is what lifts it to PF 14.4 (real BTC). The full chain: noise (PF 1.4) < random entries on real data (PF 9.9) < real signal (PF 14.4).

7. Glossary — the robustness test family

TestKills this lie
Permutation / null signals"the signal is smart" — random entries still earn 0.65%/day vs real 0.80% (p=0.0) → signal = +22%
Monte Carlo bootstrap"we were lucky with trade order" — shuffles your real trades 10k times
Walk-forward"it only worked in one period" — every 90-day window
Transaction-cost stress"fees don't matter"
Synthetic-data control"the machine is real, not lucky with structure"
Fill realism (intrabar)"the best price happened first" — 5m path inside each bar

Terms: permutation = random signals; bootstrap = reshuffle your own trades; walk-forward = out-of-sample window-by-window; null model = "what does pure luck produce?". Full beginner story: BEGINNER_GUIDE.md.
